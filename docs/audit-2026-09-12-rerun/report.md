# 情侣点单小铺体验复盘（2026-09-12 复查）

## 结论

当前体验评分：63/100。用户给出的 60 分基本准确。

软件的工程与规则完成度已经很高，但首次使用把注册、配对、安装、通知、赚币、点单同时交给用户；核心乐趣出现得太晚。最值得做的不是继续补功能，而是把前 3 分钟收成一条路径：选身份 → 连接另一半 → 立刻获得首单资格 → 发出第一个心愿 → 看到对方回应。

## 最高优先级问题

1. **底栏切页保留旧滚动位置。** 从任务返回小铺、从回忆进入“我们”时，新页面直接从中段出现。五个页面共用同一滚动容器，但切换视图没有重置或按页面保存滚动位置。这是明确的可用性缺陷。
2. **第一次使用承担了六件事。** 身份、账户、配对、安装、通知、首单同级展示，用户不知道哪一步才是真正开始。
3. **兴趣刚起来就被余额拦住。** 新用户只有 8 币，最低心愿 28 币；商品可以一路进入确认页，点击后才提示“甜心币不够啦”。应该更早展示差额和一条可完成的路径。
4. **每页重复三块固定信息。** 标题、未连接横幅、钱包卡几乎占掉半屏，真正属于当前页面的内容首屏曝光不足。
5. **空状态强调“没有”，没有制造下一次共同动作。** 订单和回忆页结构完整，但“0”“空空的”比“今天一起做什么”更抢眼。

## 建议的下一轮改版范围

### P0：先修体验断点

- 切换底栏时新页面回到顶部，或为每个底栏独立保存滚动位置；绝不能跨页面继承同一个位置。
- 余额不足时，商品卡和下单弹层直接显示“还差 19 币”，主按钮改为“去完成 2 个任务”或“连接二宝，双方各得 20 币”。
- 把开张清单从首页大卡片改成单行“下一步”，一次只出现一个动作。

### P1：重做前 3 分钟

- 选身份后不直接展示完整产品首页，进入一条短激活流。
- 激活目标只保留一句：“和二宝完成第一份互相点单。”
- 注册、创建小铺、输入情侣码都服务于这个目标；安装和通知放到首单成功后再邀请。
- 配对完成拿到 28 币时，直接推荐一个 28 币心愿，让用户一键发出第一单。

### P2：提升产品感

- 全局头部缩成一行；未连接提示只在小铺和“我们”页出现。
- 钱包卡只在小铺、任务页保留，其他页面改成顶部小徽标。
- 回忆空状态用“你们的第一件回忆”作为主角，提供“约一次会 / 写一个心愿 / 添加纪念日”三个具体入口。
- 降低大面积浅粉卡片的数量，让商品图、关系内容和对方反馈成为视觉焦点。

## 逐步审查

1. **身份选择 — 良好。** 选择清楚、触控目标大、情绪统一；“两台 iPhone”稍像设备说明而不是关系邀请。
2. **开张说明 — 需改。** 文案完整，但底部弹层首屏信息密集，主按钮贴近折叠线，且背后同时可见六项清单。
3. **任务概览 — 一般。** 规则可信、数据透明；首屏被连接横幅、钱包和两张进度卡占满，第一条实际任务落在屏幕底部。
4. **任务领奖 — 良好。** 已领取状态、余额和进度同步变化，核心正反馈成立。
5. **返回小铺 — 较差。** 页面从开张清单中段开始，标题与连接提示被裁掉，证实跨页滚动位置问题。
6. **余额不足下单 — 较差。** 用户填完时间和悄悄话、点击确认后才知道不能下单；差额和补救路径缺失。
7. **订单空状态 — 一般。** 结构清楚，有返回小铺按钮；但内容偏空，没有展示订单生命周期或第一次互动的期待感。
8. **回忆空状态 — 一般偏弱。** 数据与入口齐全，但大面积“0”强化空白，缺少第一张共同回忆的引导。
9. **我们页 — 较差。** 功能齐全，但同样从中段打开；账户、通知、设置、导出、隐私全部并列，关系内容让位给系统设置。
10. **账户注册 — 一般。** 表单清楚，协议可见；在用户还没体验到首单价值前要求邮箱密码，转化阻力高。
